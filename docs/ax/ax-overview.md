## AX とは

実務家の共通認識は「ツールを入れることではなく、**AI を前提に業務そのものを設計し直すこと**」。
よくある失敗は2つ:「PoC 止まり」と「導入しても使われない」。どちらも原因は機能ではなく運用の側にある。

## PharmaX の3つの役割

- **AI Strategist**:経営課題、投資対効果、中長期のロードマップを描く
- **Deployment Strategist**:戦略を、業務フロー・要件・検証計画・評価指標・定着施策に落とし込む ← **PdM の入口はここ**
- **FDE**(現場に常駐するエンジニア):お客さんの現場で実装し、本番運用まで担う

キャリアは PdM → Deployment Strategist → AI Strategist の順に進む想定。

求人の条件:
- 必須:PdM としてリリースまでやり切った経験、上流工程を主担当した経験、AI ツールで **自分でプロトタイプを作れること**
- 歓迎:PoC を続けるか撤退するかの判断、精度評価、AI の誤りや例外を前提にした運用設計、SQL

## AX 案件の流れ

| フェーズ | 判断すること |
|---|---|
| 1. 業務の棚卸し | どの業務を対象にするか(頻度が高い・手順の型がある・数字で測れる) |
| 2. PoC の設計 | 検証する仮説、成功基準、**本番に移す条件(誰が・いつ・どの業務を変えるか)** |
| 3. ルール作り | AI に入れてよいデータ、出力を人がどう確認するか |
| 4. 業務設計とプロトタイプ | AI に任せる範囲、人が確認する箇所、例外の扱い |
| 5. 精度の評価 | 合格ライン、誤りをどう扱うか |
| 6. 実装と本番稼働 | どこまで、どの順で広げるか |
| 7. 現場への定着 | 現場の納得をどう作るか |
| 8. 効果測定と横展開 | 次にどの業務へ広げるか、次に何を提案するか |

PdM の経験がそのまま効くのは 2〜5 と 8。定着(7)については、「研修より伴走」「プロンプトは配るのではなく現場と一緒に作る」が複数の記事で共通していた。
