## 方針

- 「課題 → 検証 → MVP → 計測 → 改善」の流れがそのまま読めるように、**ファイル番号 = 作る順番** にする。
- 前のドキュメントの結論が、次のドキュメントの前提になる。検証で前提が崩れたら、前に戻って書き直し、その経緯を `decision-log.md` に残す(手戻りもポートフォリオの材料になる)。
- 依頼にあった9項目に加えて、**インタビュー結果** と **意思決定ログ** を追加している(理由は表の下)。

## 依頼内容からの変更点と理由

1. **「インタビュー結果」(05)を追加。**
   設計(04)だけだと「検証した」ことが見えない。結果と、それを受けて課題をどう変えたかが、PdM の進め方として一番伝わる部分なので独立させた。
2. **市場規模(06)を、インタビューの後ろに置いた。**
   【推測】課題が絞れていない段階で市場規模を見積もると、「アロマ市場全体」のような大きすぎる数字になり、判断に使えない。ただし、02 でターゲットを選ぶときに桁感が必要なら、02 の中で簡単なメモだけ先に書く。
3. **AI(08)を、KPI(09)より前に置いた。**
   AI に任せる範囲が決まらないと、「AI の提案を人が修正した率」のような計測項目が決まらないため。
4. **意思決定ログを追加。**
   「選ばなかった選択肢と理由」は後から再現しにくいので、その都度残す。
