## 3. データベースの今の形

- IFRA:`ifra_amendments`/`ifra_standards`/`ifra_standard_cas`/`ifra_limits`(18カテゴリ)/`ifra_annex`/`ifra_review_items`(例外表)/`ifra_sum_groups`(柑橘のフロクマリンの足し算グループ)
  - **確認の計算(R10)は、ビュー `ifra_limits_11b_effective`(11B の「使う上限」=Excel の値に例外表の決定を重ねたもの)と `ifra_annex` を使う**
  - 柑橘(IFRA_STD_089)は `effective_kind = 'sum_group'`。グループ `furocoumarin` の8つの精油について「使用量 ÷ 上限」の合計が 100% を超えないかで見る
- 精油:`essential_oils`(名前・学名・種類・抽出部位[配列]・抽出方法・ブランド・メモ・登録の番号)/`oil_annex_links`(一致/近似/なし。Annex の精油は「名前+ISO の区分」で決まる)/`oil_standard_links`(原料そのものの基準)
- 権限:すべての表に RLS と GRANT(ログインした人=ひろみだけ)。**新しい表を作るときは、RLS と GRANT の両方を付ける**(付け忘れで permission denied になったことがある)
- 処方:`products`(ピローミスト=11B)/`formulas`(不変 ID は P+5桁を自動で振る)/`formula_lines`(精油・ノートの数字・試作時の希釈率・グループ)/`formula_sale_names`(販売名の履歴)。保存は関数 `save_formula`(処方と配合行をまとめて入れる)
- 確認の計算(ビューを順に重ねている):`formula_line_concentrations` → `formula_oil_concentrations` → `formula_check_contributions` → `formula_check_items`(基準ごとの合計と段階)→ `formula_check_board`(最新の判断を重ねたもの。画面はこれを読む)。一覧用は `formula_status`
  - Annex は、同じ行が2回入っている精油があるので、`ifra_annex_constituents`(1行にまとめたもの)を使う
- 判断と確認の記録:`formula_judgments`(足していくだけ。最新の1件を使う。画面の選択肢は「意図して超える」「処方を変える」の2つ)/`formula_checks`・`formula_check_results`(そのときの結果の写し。**判断を記録するたびに自動で保存する**。関数 `record_formula_check`)
  - 判断したあとで上限との比が上がった・段階が変わった対象は、もう一度「判断がいるもの」に出る(ひろみ「必ず入れてほしい」)
- 写真の読み取り:`formula_readings`(写真の場所・状態・AI の下書き `draft`・人が保存した配合行 `final_lines`・モデル・指示文の版・時間・トークン数)。写真は Storage の非公開の置き場所 `note-photos`(見るときは期限つきの URL を作る)
  - 写真を上げた時刻(`created_at`)と保存した時刻(`saved_at`)があるので、記録にかかった時間(R17)を出せる
- 表記揺れ辞書:`oil_aliases`(ならした書き方 `alias_key` → 精油。「毎回選ぶ」・使った回数)。保存のときに関数 `remember_oil_aliases` でまとめて覚える
- Evals:`eval_runs`(採点1回=モデル×指示文の版×思考の深さ)/`eval_results`(写真1枚ごとの採点と行ごとの見比べ)/ビュー `eval_run_summary`(一致率・1枚の時間・費用)。正解から外す印は `formula_readings.eval_excluded`
- まだ表がないもの:作業時間の記録(R17)

## 6. 進め方の約束(このチャットで決まったこと)

- 区切りごとに PR を作り(最初は下書き)、ひろみが確認版で動かして確かめてからマージ。Claude は PR を見張る
- SQL はひろみが SQL Editor で実行する。確認用の SQL(期待する値つき)も一緒に用意する
- 返事がほしい質問は、メッセージの最後に「▶ お返事がほしいこと」としてまとめる(ひろみは読み飛ばしやすいと自覚している)
- ひろみの質問と迷いは `docs/ax/questions-log.md` に記録(復習用)。節目は `docs/ax/learning-log.md`、決定は `docs/decision-log.md`
- 確認は「実際に使う人(ログインした人)の立場」で行う
- Claude の手元には Supabase がないので、画面を実際のデータベースにつないで動かす確認は、ひろみが確認版で行う。SQL は、手元の PostgreSQL に `supabase/` の migrations と seed を入れて試せる(IFRA のデータはリポジトリにある)
- 画面の写しを送るときは、配合が写らない部分(「確認の結果」など)だけにする。ドキュメントには配合を書かない
