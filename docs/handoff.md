## 3. データベースの今の形

- IFRA:`ifra_amendments`/`ifra_standards`/`ifra_standard_cas`/`ifra_limits`(18カテゴリ)/`ifra_annex`/`ifra_review_items`(例外表)/`ifra_sum_groups`(柑橘のフロクマリンの足し算グループ)
  - **確認の計算(R10)は、ビュー `ifra_limits_11b_effective`(11B の「使う上限」=Excel の値に例外表の決定を重ねたもの)と `ifra_annex` を使う**
  - 柑橘(IFRA_STD_089)は `effective_kind = 'sum_group'`。グループ `furocoumarin` の8つの精油について「使用量 ÷ 上限」の合計が 100% を超えないかで見る
- 精油:`essential_oils`(名前・学名・種類・抽出部位[配列]・抽出方法・ブランド・メモ・登録の番号)/`oil_annex_links`(一致/近似/なし。Annex の精油は「名前+ISO の区分」で決まる)/`oil_standard_links`(原料そのものの基準)
- 権限:すべての表に RLS と GRANT(ログインした人=ひろみだけ)。**新しい表を作るときは、RLS と GRANT の両方を付ける**(付け忘れで permission denied になったことがある)
- まだ表がないもの:処方・配合行・確認の結果・「意図して超えた」の記録

## 4. 次にやること(R10〜R12)の論点

- 処方の表の設計:不変 ID(P+5桁)、販売名、版(処方を変えても前の処方を残す)、配合行(精油・比率)、賦香率、試作時の希釈率(既定 10%)。docs/09 の表の一覧が出発点
- 計算:完成品中の濃度 = 配合の比率 × 賦香率。成分は「完成品中の精油の濃度 × Annex の含有率」を、同じ基準(CAS)ごとに足す。11B の上限と比べる
- 表示(R11):赤/黄/上限に近い(0.8倍以上)/未確認の精油あり/本文の確認が必要。近似のときは代用した参考値を表示
- 「意図して超えた」の記録(R12):判断と理由。記録済みの黄は次から目立たなくする
- 答え合わせ:事前検証(V2)で手作業で計算した3処方(`docs/05_validation-results.md`)と同じ結果になるか
- 処方の配合は企業秘密:データベースにだけ置き、リポジトリ・チャットには書かない
