# 07 MVP のスコープ

ステータス:**確定 v1.0(2026-11-06)**
前提:01〜06(すべて v1.0)。開発は **ひろみ+Claude Code で約60時間**(1日2時間 × 毎日 × 1か月)。

---

## 1. 考え方

1. これまでの会話で出た要求を、**すべて一覧にする**(作るかどうかは、まだ決めていない状態)。
2. それぞれの **手間** を見積もる。
3. **価値の大きさ** と手間を見て、60時間に入れるものを選ぶ。入らないものは捨てずに「次にやること」に残す。

### 手間の見積もりについて【推測】
- Claude Code と作るので、コードを書く時間は人だけで作るより短い。
- ただし、次の時間は短くならない。見積もりにはこれを含めている。
  - **確かめる時間**:ひろみが実際に動かして、正しいかを見る
  - **データを用意する時間**:例外表、精油の登録など
  - **決める時間**:画面の細かい動き、例外の扱い
  - **想定外への対応**:動かしてから分かる問題
- 見積もりは技術構成(10)を決める前のもので、**幅のある目安**。

## 3. 60時間に入るか

### Must の合計【推測】
- R1〜R5、R7〜R12、R16〜R19 の合計:**約47〜66時間**(R6 を除く)
- → **60時間ちょうど前後で、ほぼいっぱい**。

### ★R6(表記揺れ辞書)をどうするか
- ひろみが「人が作ると時間がかかりそう」と迷った機能。
- 【推測】作り方で手間が変わる。
  - **軽い版(約3時間)**:写真の読み取り結果を確認する画面で、「この書き方を覚える」を押すと辞書に登録される。辞書の一覧は表で見られるだけ(編集は最低限)。
  - **しっかり版(約6時間)**:辞書を管理する画面(検索・編集・削除・曖昧な書き方の設定)。
- 【推測】軽い版でも、ひろみの作業はかなり速くなる。V2 で分かったように、**名前の取り違えは確認結果を変えてしまう** ので、軽い版は入れる価値が高い。
- → 提案:**軽い版を Must に上げ、その分 R19(予備)を少し削る**。しっかり版は Next。

#### 決定(2026-11-06):軽い版+「間違えて覚えた書き方を消せる」
- 軽い版の流れ:
  1. AI が写真から読んだ名前が辞書にないときは、確認画面で **「不明」** と表示する。
  2. ひろみが、登録済みの精油の一覧(名前で絞り込める)から選ぶ。なければ、その場で精油を新しく登録する。
  3. 「この書き方を覚える」(最初からオン)で辞書に保存される。**次からは自動で結びつく**。
  4. 「マジョラム」のように複数の精油を指しうる書き方は、「毎回選ぶ」に設定できる。
- 【事実】ひろみの考え:「手入力した結果が保存されるなら、実質しっかり版になるから一旦それがいい」。
- 【推測】追加:**間違えて覚えた書き方を、一覧から消せる・直せる** ようにする(約1時間)。間違った結びつきが残ると、確認の結果が気づかないうちに変わってしまうため。
- しっかり版との差は、検索・一括の編集などの専用の管理画面だけになる。それは Next。
- 手間:**約4時間**で Must。

### ②を MVP に含めるか
- 03 で、「処方と瓶ごとの価格・在庫がつながること」が既存ツールとの一番の差になりそうだと分かっている。
- しかし、①だけで60時間がほぼ埋まる。
- 選択肢:
  - **(A) ①を60時間で仕上げ、②は次の段階にする** ← 提案 → **採用(2026-11-06、ひろみの判断)**
    - 理由:①は事前検証で価値を確かめられた(3処方すべてで知らなかった注意が見つかった)。②の価値はまだ検証していない(棚卸しは月に約1時間の負担)。
  - **(B) ①を削り(例:R12、R16 を後回し)、②の一部(R20・R22)を入れる**
    - 理由:既存ツールとの差を MVP で見せられる。
    - 弱み:①の確認の質が下がる。Evals を外すと、AX の「精度評価」が見せられなくなる。

## 4. 本番に移す条件(AX:PoC 止まりにしないために)

- MVP が完成したら、次の条件で「本番運用」に切り替える(2026-11-06 ひろみが了承)。
  - **いつ**:MVP 完成の翌日から
  - **何を変えるか**:**新しい処方は、すべてツールで記録・確認する**(スプレッドシートへの書き起こしをやめる)
  - **既存の処方**:販売中のピローミスト12処方を、2週間以内にツールに登録する(確認済み 3/12 → 12/12)
- 切り替えをやめる条件(案):写真の読み取りで、ひろみが直す行が **1処方あたり2割を超える** 状態が続く場合は、手入力中心に戻す。
