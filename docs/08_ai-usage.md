# 08 AI をどの業務に、なぜ組み込むか

ステータス:**下書き(2026-11-06)**
前提:`07_mvp-scope.md` v1.0(MVP は ① のみ)、`05_validation-results.md`

---

## 1. 基本の分け方

| 種類 | 担当 | 理由 |
|---|---|---|
| **読み取る・候補を出す** | AI(Claude API) | 手書きの文字、表記の揺れ、似た名前の照合など、決まったルールで書きにくい作業。V1 で汎用の OCR では読めず、AI では読めた |
| **計算する・照らし合わせる** | 計算式(SQL など) | 濃度・合計・上限との比は、決まった式で必ず同じ答えが出る。AI に任せると、まれに間違った数字を出すおそれがある |
| **決める** | ひろみ | 保存してよいか、上限を意図して超えるか。プロダクトは判断を補助するだけ(CLAUDE.md の規制の扱い) |

---

## 2. AI を使う業務(MVP)

| # | 業務 | AI がやること | 人がやること | 対応する要求 |
|---|---|---|---|---|
| A1 | 手書きノートの写真から処方を作る | 精油名・比率・グループ・小計・不変 ID を読み取り、表の形の下書きにする。読めない箇所・小計が合わない箇所に印をつける | 下書きを確認・修正して保存する | R1、R2、R3 |
| A2 | 辞書にない書き方を、精油に結びつける | 登録済みの精油から、**候補** を出す(例:「Eremi」→ エレミ) | 候補から選ぶ/新しく登録する。「覚える」かを決める | R6 ※**Want(MVP の後)**。MVP では人が一覧から選ぶ |
| A3 | 精油を IFRA の Annex に結びつける | 学名・抽出部位などから、Annex の候補と「一致/近似」の別、近似ならその理由を出す | 候補を確認して決める | R9 ※**Want(MVP の後)**。MVP では人が Annex の一覧から選ぶ |

- 【事実】2026-11-06、ひろみの判断で A2・A3 は **Want**(MVP の後)にした。MVP で AI を使うのは **A1(写真の読み取り)だけ**。
- 【推測】影響:精油と Annex の結びつけは、ひろみが一覧から選ぶ作業になる。精油50〜100本ぶんで、**ひろみの作業が数時間増える** 見込み(一度やれば済む)。

### AI に守らせるルール(V1 から)
- **辻褄を合わせない**:小計と合わなくても、数字を書き換えない。合わないことを印で知らせる。
- **分からないものは空けて、印をつける**:推測で埋めない。推測を出すときは「推測」と分かる形にする。
- **辞書を優先する**:ひろみが登録した書き方は、AI の判断より優先する。
- **決まった形で答える**:画面やデータベースに入れやすいよう、項目の決まった形(JSON など)で出力させる。

## 3. AI を使わない業務(と理由)

| 業務 | 使わない理由 |
|---|---|
| 完成品中の濃度、同じ成分の合計、上限との比 | 決まった式で計算できる。AI の計算間違いは見つけにくく、安全面の確認には致命的 |
| 赤・黄・上限に近い・未確認の判定 | 決まった基準(しきい値)で判定できる |
| IFRA の表の整形(カンマ、No Restriction など) | 決まったルールで直せる。判断が必要な6件は人が例外表で持つ |
| 「意図して超える」かの判断 | ひろみの判断。プロダクトは法的な判断をしない |
| Evals の採点 | 正解データとの比較は、決まった方法で機械的に行う |
| IFRA の基準の説明(RAG) | このプロダクトでは使わない(`ax/ax-mapping.md`)。基準の数字は表から引く |

## 4. AI が間違えたときに、どこで気づけるか

| 気づく場所 | 何に気づけるか |
|---|---|
| ① 小計のチェック(計算式) | 数字の読み間違い、行の抜け・重なり |
| ② 「読めない」「不明」の印 | AI が自信のない箇所 |
| ③ 保存前の確認画面(人) | すべての読み間違い。ここを通らないと保存できない |
| ④ 辞書の優先 | 一度直した書き方は、次から AI の判断に頼らない |
| ⑤ 近似の表示 | 精油と Annex の結びつきが「ぴったり」でないこと |
| ⑥ 直した数の記録(計測) | AI の精度が下がっていないか(09 で集計) |
| ⑦ Evals(正解データとの採点) | 指示文やモデルを変えたときに、精度が下がっていないか |

- 【推測】③で人がすべて確認するので、AI の間違いがそのまま保存されることはない。ただし、**人の確認が形だけになる(よく見ずに保存する)** と、この仕組みは働かない。⑥で「直した数が0の状態が続く」ことも、見落としのサインとして見る。

## 5. AI に送るデータ

### 送るもの
- 手書きノートの写真(処方の配合を含む。**企業秘密にあたる**)
- 登録済みの精油の名前・学名の一覧(A2・A3 の候補を出すため)

### 送らないもの
- 顧客の情報(MVP ではそもそも持たない)
- 原価・仕入れの情報(② の範囲。MVP では持たない)

### Claude API に送ったデータの扱い【事実】(確認日 2026-11-06)
- API(商用の製品)への入力・出力は、**原則としてモデルの学習に使われない**(利用者が明示的に参加した場合を除く)。
  - 出典:[Is my data used for model training?(Anthropic Privacy Center)](https://privacy.claude.com/en/articles/7996868-is-my-data-used-for-model-training)
- 保存期間は、**標準で30日**。条件を満たすエンドポイントとモデルでは、保存しない契約(Zero Data Retention)もある。保存されたデータも、明示的な許可なく学習には使われない。
  - 出典:[API and data retention(Claude Platform Docs)](https://docs.anthropic.com/en/docs/build-with-claude/zero-data-retention)
- 個人向けの規約変更(保存期間5年など)は、API には適用されない。
  - 出典:[Updates to Consumer Terms and Privacy Policy](https://www.anthropic.com/news/updates-to-our-consumer-terms)
- 有料の API 利用者は、送ったデータを個別に削除することはできない。
  - 出典:[Can you delete data that I sent via API?](https://privacy.claude.com/en/articles/7996875-can-you-delete-data-that-i-sent-via-api)
- 注意:正式な契約は Anthropic の Commercial Terms で、今回は本文を確認していない。

### 選択肢(ひろみが決める)→ **(a) に決定(2026-11-06)**。理由:手軽さを重視(ひろみ)
- (a) 写真をそのまま送る(既定の30日保存、学習には使われない)
- (b) 送る前に写真を切り取り、処方の部分だけにする(ノートのほかのページやメモを送らない)
- (c) 写真を送らず、手入力にする(A1 を使わない)
